# LLM 失败模式——文档相关子集

> `writing-agent-docs` 参考文件：与“文档 / 提示词写法”相关的 LLM 失败模式术语表。本文件是各规则 `**根因：**` tagline 所用术语的**唯一定义处**，也是作者与代理的共享词汇源——术语对齐后，症状速查表的检索命中率与作者维护时的因果追溯同时改善。
>
> 完整本体（8 类 60+ 模式）见 [R1]；本文件只收**可被文档写法缓解**的子集。

## 根因：模式匹配范式

LLM 做的是**统计上合理的续写**，而非推理、检索或校验。失败不是待修的 bug，而是范式的特征——“幻觉”“过度自信”“腐败成功”都根植于此。下表五类失败模式是这一根因在文档场景的具体投射，A–C 域每条规则都在对抗其中之一或与之相关。

## 五类文档相关失败模式

| 术语 | 口语症状 | 一句话机制 | 指向规则 |
|------|---------|-----------|---------|
| **上下文衰减**（Context Rot / Lost-in-the-Middle）| 文档越写越长、关键规则代理没看到、中部信息被忽略 | 上下文变长→指令遵从与事实准确性全面退化；首尾注意力强、中部最弱（U 型曲线） | A.1 / A.3 / B.1 / C.2 / C.3 |
| **提示词脆弱性**（Prompt Brittleness）| 语义等价的改写后行为剧变、规则一长就漂移 | 措辞 / 空白 / 顺序的微小变化不成比例地放大输出波动；基准测的是“提示特定表现”而非通用能力 | A.4 / B.3 |
| **指令遵从缺陷** | 规则被绕过、多约束代理只跟一半 | 复杂多约束最佳模型完美遵从 <30%；“指令请求，机制要求” | A.2 |
| **行为偏置** | 否定指令代理反而做了、代理过度自信、谄媚迎合 | 否定 prime 被禁行为（Pink Elephant）；“I don’t know”在语料中罕见，RLHF 奖励果断 | B.2 / C.1 / C.5 |
| **静默失败与复合衰减** | 代理说完成其实没验证、多步任务成功率骤降 | “腐败成功”占多代理报告成功的 27–78%；每步 95% 可靠→10 步 60%→20 步 36% | C.1 / C.5 |

> **时间混淆**（Temporal Confusion）单列：模型无内部时间感，仅靠训练语料的时间信号——把“当前状态”陈述为“判断标准”即可规避（M.1 升维、B.5 避免过时）。

## 两条优化支柱

大规模实验（13.2 万提示变体）发现提示词稳定性遵循“平均性能越高 ↔ 方差越低”的缩放律，由两根支柱驱动，共同“锁住”生成空间，使代码生成方差降 40.7% [R2]：

| 支柱 | 机制 | 指向规则 |
|------|------|---------|
| **领域专属术语**（Domain-Specific Terminology）| 锚定语义边界，收窄模型的解释空间 | B.3 真实值 / B.5 术语一致 / C.4 结构化 |
| **显式行动指令**（Explicit Action Directives）| 形式化推理轨迹，把“描述”变成“可执行命令” | B.1 命令优先 / B.4 命令带 flag / C.5 完成标准 |

## 如何使用本表

- **写规则时**：先问“这条规则对抗上表哪类失败？”——答不出则可能是推测性规则（A.1），不该写
- **维护规则时**：删一条前查“指向规则”列——知道会重新打开哪类失败
- **检索时**：症状速查表已括注本表术语，命中共享词汇
